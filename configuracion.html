Configuración Técnica de Equipos RAX

PASO 1: Limpieza de Residuos

¿Por qué limpiar? Los equipos RAX guardan configuraciones de servicios anteriores. Si no eliminamos las VLANs y los modos de puerto antiguos, el nuevo servicio puede presentar conflictos de tráfico o errores de etiquetado (QinQ).
show vlanIdentificar qué VLANs están ocupando los puertos actualmente.
conf tIngresar al modo de configuración global.
no vlan --ID--Eliminar la VLAN antigua para liberar el ID.
interface --PORT--Entrar a la interfaz física que vamos a reconfigurar.
no switchport modeCRÍTICO: Resetea el puerto a su estado de fábrica.

PASO 2: Definición de VLANs Activas

Lógica de Red: Se deben crear al menos dos VLANs: una para la Gestión (administración remota) y otra para el Servicio (tráfico del cliente). Sin el comando state active, la VLAN no transportará datos.
vlan --ID--Crear el identificador numérico de la VLAN.
state activeAsegura que la VLAN esté operativa en el switch virtual.
name --NOMBRE--Etiqueta descriptiva (Ej: GESTION_NODO o CLIENTE_X).

PASO 3: Configuración de Puertos NNI y UNI

NNI (Network Node Interface): Es el puerto que va hacia la red de Serena. Debe estar en trunk.
UNI (User Network Interface): Es el puerto que se entrega al cliente. Suele ser access.
interface nni --PORT--Entrar al puerto que recibe el enlace de fibra/uplink.
switchport mode trunkPermite que pasen múltiples VLANs por este puerto.
switchport trunk allowed vlan --ID--Habilitar específicamente la gestión y el servicio.
interface uni --PORT--Entrar al puerto de cobre/fibra que va al cliente.
switchport mode accessDefine que el puerto entregará una sola VLAN "limpia".
switchport access vlan --ID--Asociar el tráfico del cliente a su VLAN de servicio.

PASO 4: Interfaz de Gestión e IP

Gestión Lógica: Los RAX usan una "IP Interface" para que el equipo sea visible en la red. Siempre se usa la interface ip 0. Sin gateway, el equipo no podrá ser alcanzado desde fuera de su propia red.
